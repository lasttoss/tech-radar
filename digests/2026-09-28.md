# 2026-09-28 — the scan that produced the verdicts

Not a daily digest: a scan of the Hub and GitHub over twelve months, aimed at one
question — is there anything better than the current approach for reading a game
frame and generating something playable from it. Recorded here because the verdicts
in `decisions/` come out of it.

Twelve angles were queried: screenshot to code, game reconstruction, world models,
sprite extraction, video to code, UI grounding and so on. Rows that mattered:

| item | why it mattered | verdict |
|---|---|---|
| `Qwen/Qwen3-VL-8B-Instruct` | candidate for reading state out of a frame | reject - empty content, all of it in the thinking block |
| `Qwen/Qwen2.5-VL-7B-Instruct` | the baseline already served locally | watch - 6/7 fields, 9.1s, 62 tokens |
| `Anionex/agent-vision-toolkit` | gives a text-only model image abilities | watch - and it is the reason the harness was checked first |
| `abi/screenshot-to-code` | the largest project in screenshot-to-frontend | not tried |
| `Riemann-Dynamics/Matrix-Game-3.5` | an interactive world model - a different way to build something playable | not tried |
| `cathrynlavery/diagram-design` | editorial diagrams as self-contained HTML and SVG, deliberately not Mermaid | not tried |

Method and numbers: `experiments/2026-09-28-frame-state-reading.md` and
`experiments/2026-09-28-generated-page-from-frame.md`.
